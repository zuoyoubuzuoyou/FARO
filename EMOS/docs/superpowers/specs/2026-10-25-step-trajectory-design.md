# 按环境 step 保存的统一轨迹设计

状态：已于 2026-10-25 实施并通过离线验证。用户已选择“按照环境 step 保存”，并要求保留按历史 LLM 决策从头重跑所需信息。实际使用见 [轨迹说明](../../step_trajectories.md)。

## 目标与范围

新轨迹以每次实际返回的 `env.step` 为主单位：`steps.jsonl` 每行一个环境步，包含该步动作、返回状态、奖励、指标，以及本步相关决策、模型调用、通信、故障和异常的有序记录。

保留 V2 的模型请求证据、精确动作阶段、终止原因和来源信息，补充 V1 的决策后 agent/通信上下文。重点消除重复正文和状态副本，不降低环境步采样率或状态数值精度。

本次实现覆盖录制、统一读取、检测/恢复/稳定性消费者适配，以及回放所需上下文的采集与重建验证。当前 rsi 没有旧分支的执行回放入口；完整回放执行器迁移属于后续功能，本次不能将“数据可重建”宣称为“真实仿真已经回放成功”。不新增真实 API/仿真实验，不改写历史轨迹。

## 已选方案及替代方案

- 采用用户选定的每环境步一行方案：保留现有采集 hooks 和事件顺序，磁盘将事件按环境步归组，统一读取器可展开为现有事件接口。
- 继续每事件一行：已有消费者改动少，但没有采用用户要求的主要保存单位。
- 全量状态增量协议：可进一步压缩，但增加随机读取、损坏恢复和调试成本；第一版仍逐步保存完整动态状态。

以下具体字段和容错安排采用先前已展示的设计，由实现测试验证。

## 文件组织

```text
<run_directory>/
  config.json
  episodes/<episode_directory>/
    episode.json
    steps.jsonl
    pending.json
    summary.json
    payloads/<sha256>.json
    media/<sha256>.<ext>
```

2026-10-26 目录命名更新：运行目录为北京时间 `run_YYYYMMDD_HHMMSS`，同秒重复加 `_02` 等；episode ID 2 对应 `episode_0002`，重复尝试加 `_attempt_02` 等。内部 UUID 身份保持不变，config 索引记录实际目录。旧目录格式继续兼容读取。

- `config.json`：运行配置、模型配置版本、seed、原生成功定义、代码/输入/提示词来源；新录制不重复生成同内容 `run.json`。
- `episode.json`：完整 run/scene/episode/evaluation/env 身份、任务/场景描述、初始真实状态、初始事件和格式说明。初始状态为 step 0，但不是一次已经执行的环境步，不写进 `steps.jsonl`。
- `steps.jsonl`：只写实际返回的环境步，1 到 N 连续编号，一步一行；339 个环境步对应 339 行。兼容读取器必须验证连续性和 episode 身份。
- `pending.json`：原子更新的当前未提交步记录。模型请求等在环境动作发生之前即落盘；若 API 出错、进程中断或环境调用失败，保留已有证据，不伪造新的已执行环境步。提交步后清除该步 pending 内容；硬中断后的读取只恢复完整记录。
- `summary.json`：完成/中断/错误状态、原生成功值、终止原因、步数和统计；最终大状态引用最后一步，未完成不能当作原生失败。
- `payloads/`：内容寻址的大字段，先写正文再写引用；用于复用消息、工具定义、完整响应和决策上下文。引用损坏、越界或哈希不符必须明确报错。
- `media/`：保留实际模型输入图像；额外决策 RGB 截图维持现有行为以避免这次引入独立配置变化，后续可另行选择关闭。

## 每步字段

```json
{
  "schema_version": 3,
  "step": 1,
  "action": [],
  "reward": 0.0,
  "done": false,
  "metrics": {},
  "state": {},
  "events": [],
  "replay_context": {}
}
```

示意中的空值仅为展示结构，不代表真实采集缺失时使用空对象填补。

- 该步 `action` 保存最终提交的联合向量；`state.executed_action` 保存环境入口转换后的 Habitat 命令，二者语义不同。
- `state` 保存 worker 自动 reset 前的机器人底座位置/四元数、末端位置、持物 ID、目标物体身份/位置/目标位置及任务状态。保持 unknown/null 与明确 false 的差别。
- 环境原生 `state.task_progress` 与加入策略信息后的 `metrics` 分别保留来源，只有实际内容相同时才复用内容，不假定同名指标相等。
- `events` 按原来的全局 `sequence` 排序，保留原始 `env_step`、角色、phase、call/action/decision ID 及相关处理结果。首版保留事件中的静态身份，读出时与 episode/步身份交叉校验；去重集中于较大的正文、上下文和状态。
- 大字段通过引用复用，调用的完整有序 messages、显式 kwargs、tools/tool_choice、未发送参数来源、SDK timeout/retry、原始响应、usage、错误和耗时都可还原。
- 同步回调仍收到原来展开的事件，采集时机、动作选择和在线恢复时序不变；磁盘归组不应改变执行行为。

## 决策、回放和通信

- 保留“模型建议→解析/转换→实际技能进入→最终环境动作”的关联，包含 send_request 转 wait、无效动作回退、robot 参数注入、占位工具消息等区别。
- 保留 action start/end 与终止信号，尤其 timeout 后未交接与后续交接；不能将相同步号的事件重新按类型排序。
- 在真实新决策后保存 agent 的分组 chat_history、system_message、任务/子任务、初始化状态、start_act、planner_plan、影响请求的模型/window 配置、恢复动作和反馈；长正文以消息/分组引用去重，不仅依赖“下一次请求”反推历史。
- 保存当前 rsi `CrabAgent.message_pipe` 中收件人对应的有序消息列表及决策 actor 顺序；不虚构旧分支才有的消息总线字段。
- 失败尝试和回滚事件仍保留，但需要区分实际生效的决策和已回滚尝试。
- 第一个环境步前的讨论/规划/首轮执行调用归入第 1 步 pending；若第 1 步从未执行，则仅存在 pending 和错误/中断 summary。

## 去重原则

- 完整动态状态、指标和环境命令每步只保存一份，其他动作事件引用它们。
- messages 与 request_kwargs.messages、raw_response 与 message/usage 等重复正文只保存一次；读取接口可恢复旧字段。
- 相同消息跨请求与回放上下文复用；chat_history 分组和消息顺序不可丢失，不假定历史只追加。
- 同一名称但值/阶段不同的动作或指标不得合并；仅在确认相同后复用数据。
- 全局唯一事件 ID 或 sequence 所需映射必须保留，不能因为同一 env_step 就丢失事件顺序。
- 真正采集失败的 missing_fields 保留；“环境事件不属于单个 agent”等正常不适用字段可由 schema/读取器补全。

## 兼容、验证和验收

- 统一读取器支持历史 V1、V2 和新 V3；新的检测、恢复和稳定性检查统一通过该读取器消费。不得只修改输出而让现有消费者静默漏读。
- 旧结果文件及实验 manifest 不改写；新录制的 summary 文件索引指向 `steps.jsonl`。
- 测试覆盖：每环境步一行、模型事件归组、讨论/规划、终局前后顺序、首次决策错误、环境步错误、pending 原子提交与重复恢复、缺失/损坏引用、外来 episode 身份、timeout/交接、回放上下文完整重建、多环境/重复 episode 命名。
- 用当前 episode 78 的真实 V2 文件进行离线归组与展开验证，核对全部 339 个环境转换及关键事件/消息/指标一致，测量体积变化；不启动新仿真或 API 请求。
- 跑现有轨迹、检测、恢复和稳定性相关单元测试，确认原生成功、中断状态和缺失证据判定不变。
- 实施后明确报告：代码验证、离线历史数据验证和真实场景回放验证分别完成了哪些，不能混称。


### 1. 研究问题

现有 Embodied Multi-Agent benchmark 通常假设 observation、action、communication、memory 和 planning 都比较可靠，但真实世界中并非如此。

我们关注的不仅仅是 **agent dropout / agent 消失**，而是：

> **Agent 仍然正常运行，但它的感知、记忆、通信、规划或动作已经出错。**

暂时可以把这种问题称为 **Latent Execution Fault**。

核心问题只有两个：

**Q1：如何系统、可控地模拟这些错误？**  
**Q2：如何让多智能体系统在线发现并恢复这些错误？**

---

### 2. 第一部分：Fault Injection Layer

先做一个通用的错误注入层，接到现有 embodied benchmark 上。

第一步我想先对目前具身多智能体系统的研究中存在的错误进行一个分类(Level 1)，每一个错误类别下面又有一些实例(Level 2)，我想好的一些错误类型和实例：

### L1-1 Structure Fault：智能体与拓扑故障

描述团队成员的可用性、身份或角色配置异常。

- ST-1 Agent Dropout：智能体退出团队或进程崩溃，无法继续参与任务。
- ST-2 Agent Responsiveness Degradation：智能体挂起、停止响应或响应显著变慢，影响团队协作。
- ST-3 Agent Configuration Mismatch：智能体的组织身份绑定错误，或加载了错误的角色、prompt、策略。

---

### L1-2 Perception Fault：感知故障

描述原始观测到语义感知结果之间产生的错误。

- PF-1 Object Localization Error：物体的位置、深度或距离估计错误。
- PF-2 Object Recognition Error：对物体的存在、类别或属性判断错误，包括误检、漏检、误分类，以及颜色、大小、开关状态等属性错误。
- PF-3 Spatial Relation Error：错误判断 inside、on、near、connected 等空间关系。
- PF-4 Agent Perception Error：未发现其他智能体，或根据观测错误识别其身份及正在执行的动作。

遮挡作为致错原因，按照实际造成的定位、识别或空间关系错误归入对应类别。

---

### L1-3 Memory Fault：记忆与上下文故障

描述信息在写入、保存、检索、压缩或注入 LLM 上下文时产生的错误。

- MF-1 Memory Integrity Error：历史信息未被正确保存、保存后丢失、被修改为错误内容，或同一事件被重复记录。
- MF-2 Memory Retrieval Error：检索到与当前任务无关或错误的记忆，或未检索出已经存在的必要记忆。
- MF-3 Context Distortion：历史摘要改变原意，或上下文压缩、截断、组装过程中遗漏关键历史信息，导致决策上下文失真。

---

### L1-4 Planning Fault：规划故障

描述目标形成、任务分解、计划组织及计划更新过程中的错误。

- PL-1 Goal Formulation Error：形成与原始任务不一致的目标，或生成无法执行、无意义、重复或不必要的子目标。
- PL-2 Subgoal Omission：遗漏完成任务所必需的子目标或步骤。
- PL-3 Plan Dependency Violation：计划中的动作顺序错误、遗漏依赖关系，或安排在前置条件不满足时执行动作。
- PL-4 Planning Stagnation：环境或队友状态变化后仍沿用失效计划，或反复生成、执行相同计划而没有进展。

---

### L1-5 Communication Fault：通信故障

描述消息在传输和语义表达过程中产生的错误，分为传输层和语义层。

- CF-1 Message Delivery Error：消息丢失、延迟、乱序、重复，或内容在传输过程中损坏、截断。【传输层】
- CF-2 Message Addressing Error：消息发送给错误的智能体、遗漏必要接收者，或消息的发送者身份被错误标记。【传输层】
- CF-3 Referential Error：消息中的指代不清，或发送者和接收者对同一名称指向不同对象。【语义层】
- CF-4 Message Validity Error：消息内容已经不适用于当前状态，或接收者收到相互矛盾的信息。【语义层】

---

### L1-7 Coordination Fault：任务分配与协调故障

描述多个智能体之间的任务分配、资源使用与协作执行异常。

- CO-1 Task Assignment Error：同一任务被错误地重复分配、必要任务无人承担，或同一智能体收到相互冲突的任务。
- CO-2 Resource Conflict：多个智能体争用同一物体、工具或空间资源，包括路径相互冲突造成的阻塞、拥堵或碰撞风险。
- CO-3 Coordination Stagnation：多个智能体相互等待，或持续调整、避让，但无法取得任务进展，包括死锁和活锁。
- CO-4 Collaboration Protocol Violation：智能体违反协作约定，包括跨智能体前置任务未完成就启动后续任务、同步或会合失败、交接遗漏状态或物体，以及执行中偏离职责。

---

### L1-8 Capability Fault：能力、工具与资源故障

描述任务要求与智能体实际能力、工具条件或物理可达性之间的不匹配。

- CA-1 Capability Mismatch：任务被分配给不具备相应能力的智能体，或高估其负载、速度、推理能力等。
- CA-2 Tool Suitability Error：执行任务所需的工具或技能不可用，或所选工具、技能不适合当前任务。
- CA-3 Tool Timeout：工具或底层技能调用超时，未在规定时间内完成或返回结果。
- CA-4 Reachability Violation：目标超出机械臂的工作空间或移动平台的可达范围。

---

### L1-9 Action Fault：动作与执行故障

描述动作下发、实际执行及底层执行状态返回中的异常。

- AF-1 Action No-op：命令已经发出，但执行器或底层技能没有产生预期动作。
- AF-2 Action Mismatch：下发或执行的动作与应执行动作不一致，包括动作类型错误、目标对象错误、不必要地重复已完成动作，以及推理与实际下发动作不一致。
- AF-3 Execution Deviation：动作执行偏离预期参数、过程或完成程度，包括参数错误、执行漂移、部分完成、抓取失败、滑落及动作中断。
- AF-4 Motion Failure：机器人移动或机械臂运动未能安全到达目标，包括偏航、卡住、无法到达，以及与环境、物体或其他智能体碰撞。
- AF-5 Execution Reporting Error：底层技能返回的执行状态与实际结果不一致，包括动作失败却返回 success，或动作成功却返回 failure。

---

### L1-10 Verification Fault：验证故障

描述对动作或任务结果进行检查时出现的验证缺失、不完整或判断错误。

- VF-1 Verification Coverage Error：完全没有检查动作或任务结果，或只检查了部分必要完成条件。
- VF-2 Verification Misjudgment：将实际失败判断为成功，或将实际成功判断为失败。
- VF-3 Cross-agent Verification Failure：验证智能体盲目接受其他智能体的声明，或多个验证智能体对同一结果给出相互矛盾的结论。
